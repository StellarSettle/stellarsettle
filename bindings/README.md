# Contract TypeScript bindings

Typed TypeScript clients generated from the Soroban contract specs with
`stellar contract bindings typescript`. Each directory is a standalone npm
package that builds with `npm install && npm run build`.

| Package | Contract | Status |
| --- | --- | --- |
| [`loan_manager/`](loan_manager) (`@stellarsettle/loan-manager-bindings`) | `contracts/loan_manager` | Generated |
| `stellarsettle/` (`@stellarsettle/stellarsettle-bindings`) | `contracts/stellarsettle` | Generated by the same command once the contract compiles again (see below) |

## Regenerating

Run the generator from the repository root after any contract change. It
builds the WASM with `stellar contract build`, regenerates the package,
renames it to its `@stellarsettle/*` scope and builds it to check that it compiles:

```bash
scripts/generate-bindings.sh                  # every contract
scripts/generate-bindings.sh loan_manager     # one contract
scripts/generate-bindings.sh stellarsettle

# Generate from a deployed contract's on-chain spec instead of a local build
scripts/generate-bindings.sh stellarsettle --contract-id C... --network testnet
```

Use `--skip-build` to reuse an existing `target/wasm32v1-none/release/<contract>.wasm`
and `--no-verify` to skip the npm build. Commit everything under `bindings/` except
`node_modules/` and `dist/` (both are git-ignored).

> **Note:** `contracts/stellarsettle` currently fails to compile on `main`
> (missing `DataKeyExt4` variants and related types), so its WASM, and with it
> its bindings, cannot be produced yet. Once the contract builds, run
> `scripts/generate-bindings.sh stellarsettle` and commit `bindings/stellarsettle/`.
> No code changes are needed.

## Usage

```ts
import { Client } from "@stellarsettle/loan-manager-bindings";

const loanManager = new Client({
  contractId: process.env.LOAN_MANAGER_CONTRACT_ID!,
  networkPassphrase: "Test SDF Network ; September 2015",
  rpcUrl: "https://soroban-testnet.stellar.org",
});

// Read-only calls are simulated; `.result` is already decoded and typed.
const { result: position } = await loanManager.get_position({ user: "G..." });
const { result: [totalDeposits, totalBorrowed] } = await loanManager.get_pool_info();

// State-changing calls return an AssembledTransaction to sign and send.
const tx = await loanManager.borrow(
  { user: "G...", amount: 1_000_000n },
  { publicKey: "G..." },
);
await tx.signAndSend({ signTransaction }); // e.g. Freighter's signTransaction
```

Consumers in this monorepo can depend on a package by path, for example
`"@stellarsettle/loan-manager-bindings": "file:../bindings/loan_manager"`, after
running `npm run build` in the bindings directory.

### loan_manager coverage

- Liquidity: `deposit`, `withdraw`, `get_depositor_balance`, `get_depositors`
- Borrowing: `deposit_collateral`, `borrow`, `repay`, `withdraw_collateral`
- Liquidation: `liquidate` (returns a typed `LiquidationResult`)
- Lending UI reads: `get_position`, `health_factor`, `get_pool_info`, `get_market_config`,
  `get_liquidation_params`, `preview_price`, `get_twap`, `twap_now`, `get_oracles`,
  `is_paused_view`, `get_admin`
- Admin: `init`, `set_oracles`, `set_market`, `set_liq_params`, `pause`, `unpause`, `record_price`
